지금 이 저장소의 깃을 정리해줘. 나는 깃 초보라서 쉬운 말로 설명해줘. 삭제는 절대 먼저 하지 말고, 반드시 조사 → 보고 → 내 승인 → 실행 순서로 해.

1단계. 조사 (아무것도 바꾸지 않는다)
- `git fetch --prune`으로 원격 정보를 갱신한다.
- 현재 브랜치와 변경 안 된 파일(uncommitted)이 있는지 확인한다. 있으면 먼저 알려준다.
- 로컬 브랜치와 원격 브랜치 목록을 모두 본다.
- 각 브랜치를 이렇게 분류한다.
  a) 이미 main에 합쳐진 것. 일반 머지는 `git branch --merged main`으로, squash 머지는 `gh pr list --state merged`로 PR이 머지됐는지 확인한다.
  b) 아직 합쳐지지 않았고 main에 없는 고유 커밋이 있는 것. `git log main..브랜치`로 확인한다.
  c) 다른 브랜치와 내용이 거의 겹치는 것. 이전 브랜치 위에 쌓여서 같은 커밋을 공유하는 경우다.

2단계. 보고
- 표로 보여준다. 열은 브랜치 이름, 분류(a/b/c), 마지막 작업 날짜, 한 줄 설명이다.
- 어떤 브랜치를 지워도 안전한지, 어떤 브랜치는 작업이 사라질 수 있어 위험한지 구분해서 알려준다.
- b에 해당하는 브랜치는 "이 작업이 main에 없다"고 분명히 알려주고, 합칠지 버릴지 나에게 묻는다.

3단계. 승인 후 실행
- 내가 "OK"라고 한 브랜치만 로컬과 원격에서 삭제한다.
- 합치기로 한 브랜치는 PR을 만들고, 내가 승인하면 머지한다.
- main으로 돌아가 `git pull` 한다.
- `git push --force`나 `git reset --hard` 같은 되돌릴 수 없는 명령은 쓰지 않는다. 꼭 필요하면 이유를 설명하고 따로 허락을 받는다.

4단계. 마무리 보고
- 지운 브랜치, 남긴 브랜치, 합친 브랜치를 한국어로 짧게 정리해서 알려준다.
